# 동행금융 · 2026 금융 AI Challenge 실행 계획

작성: 2026-09-05. 서비스 실사와 공식 공고를 바탕으로 정한 우선순위다. 우승 확률이나 공개되지 않은 심사 배점을 수치로 추정하지 않는다.

## 승부를 걸 문제

**“매출이 똑같이 20% 줄었어도, 감소 원인과 회복 근거를 변수로 결합하면 평가항목의 결과를 다르게 설명할 수 있다.”**

동행금융은 정형 금융데이터 48개, 사업 맥락 30개, 결합 변수 16개를 현재 상황·개선가능성의 두 평가축으로 연결한다. 차별성은 **원천 → 변수와 상태 → 규칙 → 항목 배점 → 환산 결과 → 검토·재평가**를 추적할 수 있다는 데 둔다. 인터뷰는 맥락 입력 수단이며 제품과 발표의 중심은 변수화·결과 산출·평가지표 반영이다. 94개라는 개수 자체를 성능 지표로 내세우지 않는다.

현재 제품의 두 경로를 정확히 설명한다.

- 주 경로: 서비스 소개 → 합성 사례 선택 → 정형 입력만/맥락 변수 결합 전환 → 94개 변수에서 10개 평가항목까지 추적 → 산식·분모·제외 항목 확인 → CB 대조 → 목표·수행기록 → 재평가 → 기관 검토 요약.
- 보조 체험: 방문자가 답변 → AI 대화 → 원문과 구조화 정보 확인 → 상담 메모. 실제 답변으로 수행한다.
- 현재 모델은 예측 성능을 입증한 학습모델이 아니다. 실제 체험 기록에 은행 데이터를 자동으로 결합하는 기능은 아직 없으며, 서비스 소개에서 이 범위를 명시한다.

## 9월 7일 전에 할 일

1. **모델 중심 검토 경로 고정**: 공개 홈 → 서비스 소개 → 평가 반영 → 변수 선택 → 항목·산식 확인. 로그인과 개인 정보 입력 없이 핵심 결과에 도달한다. 직접 인터뷰는 별도 체험으로 둔다.
2. **심사자가 스스로 확인할 세 사례 준비**: 손님 감소 / 영업일 감소 / 답변 없음. 48개 정형 입력을 고정하고 맥락 변수를 제거·결합한 결과를 대조한다. 영업일 사례는 개선가능성 40→67.5지만 분모도 60→80으로 변하므로 27.5점을 순수 기여도로 부르지 않는다.
3. **공식 양식 PDF 완성**: 아래 문장 구조를 사용하되 등록된 팀명·구성원과 이미지 이용권을 사실에 맞게 채운다. 아직 확인하지 못한 팀 정보와 실증 성과를 만들어 쓰지 않는다.
4. **제출 증적 보관**: 배포 이미지 식별자·검증 로그·PDF 해시·실제 제출 내역을 기록한다. 동의 없는 실제 고객 자료는 제출에 포함하지 않는다.
5. **접근 유지 확인**: 공개 종료 설정은 9월 12일 00:00 KST다. 심사 기간 안에 종료되지 않게 확인한다. 단일 VM 장애 대응 담당과 복구 절차를 정한다.

## 본선 경쟁력을 높일 실증 계획

마감 전 기능 확대보다 검증 가능한 성과를 추가하는 편이 유리하다는 판단이다. 아래 숫자는 **실험 설계 목표**이며 측정 결과가 아니다. 사람 모집이나 외부 연락은 수행하지 않았다.

| 실험 | 방법 | 기록할 값 |
|---|---|---|
| 계산 정합성 | 10개 사례 × 전후 2모드 × 2축. Python 재실행과 웹 산출 결과·산식·분모 대조 | 일치율, 분모 오류, 제외값의 0점 혼입, 사례 혼선 |
| 규칙 경계·민감도 | 현재 사례에서 미실행된 13개 구간과 임계값 직전/동일/직후를 별도 사례로 추가 검증 | 구간별 실행 비율, 의도한 단조성, 작은 입력 오차가 만든 배점 차이 |

발표 자료에는 분모·과제·날짜·실패 사례를 포함한 실제 측정만 넣는다. 규칙 점수는 예측력 검증 이전까지 상담 담당자의 근거 검토용으로 한정한다. 실제 민감정보를 사용하는 후속 서비스 설계는 별도 동의·권한·보존 정책 검토 후 진행한다.

## 15분 발표 구성

문제·대상 2분 → 변수화·결합 구조 2분 → 결과·산식·평가 반영 시연 4분 → 규칙 검증·누락·민감도 3분 → 검토 업무 효과와 사용자 Flow 2분 → 실제 데이터 연동·성과 검증 계획 2분. 질의응답 5분에는 “AI 구조화가 평가에 어떤 값을 제공하는가”, “결과가 바뀐 이유를 재현할 수 있는가”, “합성 검증과 실증 성능의 경계는 어디인가”를 우선 준비한다.

실증이 없으면 해당 구간은 미측정으로 명시하고 시험 설계와 현재 확보된 기술 검증만 제시한다.

## 원안 반영 후 제출 설명

서비스의 목적을 일회성 분석에서 사업·행동 변화를 근거로 재평가와 기관 검토를 준비하는 흐름으로 보완했다. 원안 10장별 구현 매핑과 실제 제공 범위는 [기획안 반영 기록](PLAN_ALIGNMENT_2026-09-05.md)을 따른다. 성과 수치는 합성 규칙 검증과 실제 사용자 실증을 구분한다.
