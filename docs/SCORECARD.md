# 판정 규칙 (스코어카드)

현재 상황과 개선가능성을 각각 100점으로 내는 2축 점수이다.
CB 점수 옆에 나란히 표시하는 심사 참고자료이며 승인, 거절 판단이 아니다.

## 항목 선정 기준

- 비율, 일수, 개월수처럼 규모와 무관한 값만 쓴다. 금액 그대로는 쓰지 않는다.
  큰 가게가 유리해지지 않게 하기 위해서이다
- 거래 데이터에서 계산되는 값, 또는 진술이라도 데이터로 대조 확인된 값만 쓴다.
  진술 단독 항목(단골 비중, 가계지출)은 점수에서 빼고 화면에 표시만 한다
- 재료가 겹치는 항목은 하나만 쓴다. 고정비 비중을 뺀 것도 그래서인데, 고정비가
  높아도 남으면 문제가 아니고 그 결과가 이미 "남는 비율"에 들어 있다
- 배점은 항목 간 균등하다. 어느 항목이 더 중요한지 정할 근거가 아직 없으므로
  차등을 주지 않고, 실데이터가 쌓이면 조정한다

## 축 2. 개선가능성 (5항목, 각 20점)

나아질 여지가 있고 그 방향으로 가고 있는지 본다. 인터뷰가 점수를 바꾸는 축이다.

| 항목 | 재료 | 구간 | 점수 |
|---|---|---|---:|
| 매출 방향 | `fin_sales_growth_3m` + 원인 구분 + 추가 질문 답 | +5% 이상 | 20 |
| | | -5%~+5% 유지 | 12 |
| | | 하락, 사유 확인, 해소됨 | 10 |
| | | 하락, 사유 확인, 진행 중 | 4 |
| | | 하락, 사유 없음 | 0 |
| 저점 회복 | `biz_sales_recovery_from_trough` + `biz_sales_drawdown_from_peak` | 고점 대비 하락 10% 이내 | 20 |
| | | 회복 중 (저점 대비 +30% 이상) | 14 |
| | | 저점 정체 | 4 |
| | | 지금이 제일 낮음 | 0 |
| 잡혀 있는 계약 | `own_booking_coverage_weeks` + `own_confirmed_order_deposit_flag` | 8주 이상, 계약금 확인 | 20 |
| | | 4주 이상, 계약금 미확인 | 12 |
| | | 4주 미만 | 6 |
| | | 없음 | 0 |
| | | 해당 없음 업종 | 제외 |
| 비용 줄일 여지 | `imp_cost_adjustment_headroom` | 유출의 30% 이상 조정 가능 | 20 |
| | | 15~30% | 12 |
| | | 5~15% | 4 |
| | | 5% 이하 (반복 출금이 거의 전부) | 0 |
| 계획의 현실성 | `own_goal_stretch_ratio` + `own_plan_budget_to_cashflow_ratio` + `imp_goal_data_alignment` | 목표 배수 1.5배 이하, 예산이 월 현금흐름 1배 이하, 목표가 데이터와 맞음 | 20 |
| | | 목표 배수 1.5배 초과 또는 예산 부담 큼 | 8 |
| | | 결합 Feature 방향 신호는 목표 배수 2배도 강도 경계로 사용 (점수 경계는 1.5배) | 참고 |
| | | 목표가 데이터가 가리키는 문제와 어긋남 | 한 구간 아래 |
| | | 목표 안 정함 | 0 |

매출 방향의 "사유 확인"은 원인 구분과 추가 질문 답으로 판정한다.
원인 구분은 손님 수, 1인당 결제액, 영업일 중 무엇이 하락의 원인인지 보는 것이다.
규칙은 아래와 같고 경계는 임시값으로 modeling/thresholds.py에 있다.

- 3개월 매출 증가율이 -5%보다 위면 하락으로 보지 않고 분해하지 않는다
- 영업일을 먼저 본다. 영업일이 -10% 이하로 줄었고 영업일당 매출 증가율이 ±5% 안이면
  영업일이 원인이다. 문 연 날의 장사는 그대로이므로 손님 수가 같이 줄어 있어도
  날짜에서 온 하락으로 본다
- 그다음 손님 수 증가율과 1인당 결제액 증가율을 비교해 한쪽이 5%p 이상 더 내려갔으면
  그쪽이 원인이다
- 차이가 5%p 미만이거나 재료가 없으면 분해 불가(복합)로 본다

| 원인 구분 | 추가 질문 답 | 구간 |
|---|---|---|
| 영업일이 원인 | 건강, 가족이고 해소됨 = 예 | 해소됨 (10점) |
| 영업일이 원인 | 일손이고 해소됨 = 예, 반복 출금도 늘었음 | 해소됨 (10점) |
| 영업일이 원인 | 일손이고 해소됨 = 예, 반복 출금은 그대로 | 진행 중 (4점) |
| 영업일이 원인 | 건강, 가족, 일손이고 해소됨 = 아니오 | 진행 중 (4점) |
| 영업일이 원인 | 수요 감소, 사업 축소 | 진행 중 (4점) |
| 영업일이 원인 | 무응답 | 사유 없음 (0점) |
| 손님 수나 1인당 결제액이 원인 | 추가 질문 없음 | 진행 중 (4점) |
| 분해 불가(복합) | | 사유 없음 (0점) |

손님 수나 1인당 결제액이 원인인 하락은 수요나 가격의 문제라 끝난 일이 아니므로 진행 중으로 본다.

잡혀 있는 계약의 구간은 몇 주치인지로 정하고 계약금은 만점 조건에서만 본다. 계약금을
구간 조건에 먼저 두면 계약금을 받은 사장님이 못 받은 사장님보다 낮은 구간으로
내려가기 때문이다.

일손 부족이 풀렸다는 답만 데이터로 대조한다. 사람을 새로 썼다면 반복 출금이 늘어
있어야 하므로 `fin_recurring_outflow_growth_3m`이 5% 이상일 때만 해소로 본다. 건강과
가족 일은 거래 데이터에 흔적이 남지 않아 진술 그대로 받는다. 구인난은 보통 끝나는
일이 아니라 이어지는 문제인데 진술 하나로 6점이 달라지므로, 대조할 것이 있으면
대조한다.

## 결측 처리

- 계산 안 된 항목은 0점이 아니라 제외하고, 남은 항목의 만점 합으로 100점 환산한다
- 몇 항목으로 계산했는지 같이 적는다. "5항목 중 4항목으로 산출"
- 잡혀 있는 계약의 해당 없음 업종도 같은 방식으로 제외한다
- 매출 변동계수(`biz_sales_cv_6m`)가 0.5 이상이면 매출 방향과 저점 회복 항목을
  제외하고 "매출 오르내림이 커서 방향 판단 제외"를 표시한다
- 한 축에서 산출 가능한 항목이 하나도 없으면 0점이 아니라 점수 자체를 내지 않고
  산출 불가로 표시한다
- 계획의 현실성에서 "목표 안 정함" 0점은 다시 물어도 안 정한 경우(UNDECIDED)뿐이다.
  재평가처럼 인터뷰 자체가 없어 목표가 MISSING이면 0점이 아니라 제외한다

## 업종 벤치마크

업종 평균과의 대조값(`ext_` 12필드)은 점수에 넣지 않고 화면에 나란히 놓기만 한다.
데이터 담당의 계약도 12필드 전부 `context_only`이다. 벤치마크 파일을 치웠을 때와
점수가 같은지 검증이 매번 확인한다.

## 대조 불일치

진술과 데이터가 벌어진 것(`fin_sales_consistency_score` 등)은 점수에 넣지 않고
확인 필요 표시만 한다. 현금 장사면 벌어지는 것이 정상이므로 감점 근거가 되지 않는다.

## 구간과 배점의 근거

- 항목 선정: 심사가 확인해야 할 다섯 가지(현재 상황, 방향, 앞으로 들어올 것, 목표,
  버틸 수 있는지)에서 왔다. 현재 상황 축이 첫째와 다섯째를, 개선가능성 축이 나머지
  셋을 맡는다
- 구간 경계(10%, 60일, 1.5배 등): 대부분 임시값이고 데이터 근거가 없다.
  modeling/thresholds.py에 모아 두고 실데이터로 조정한다
- 매출 대비 상환 부담의 10/20/30%는 공개 통계로 크기를 견줘 봤다. 2023년
  소상공인실태조사의 기업체당 연 매출 1억 9,900만원(월 1,658만원)과 부채액
  1억 9,500만원을 놓고 금리 5%, 만기 5~10년으로 월 상환액을 계산하면 매출 대비
  12~22%가 나온다. 세 경계가 이 범위에 걸친다. 다만 금리와 만기는 가정이고
  발표된 분포가 아니므로 크기 감각의 근거로만 쓴다
- 배달 비중 질문의 기준 30%도 같은 방식이다. 온라인 음식서비스 거래액(2024년 29.3조원)을
  음식점 및 주점업 총매출(2024년 161.1조원)로 나누면 업종 평균이 18% 안팎이다.
  분자에 자체 배달이 빠지고 분모에 주점업이 들어가 정확한 값은 아니므로,
  "업종 평균보다 확실히 높은 쪽"을 고르는 값으로만 쓴다
- 배점 균등: 차등을 줄 근거가 없어서이다. 근거 없는 가중치를 만들지 않는다

## 한계

- 이 점수가 실제 연체, 상환과 관계있는지 확인되지 않았다. 정답 데이터가 0건이라
  검증 자체가 불가능한 단계이다. 그래서 심사 참고자료이며 승인 판단에 쓰지 않는다
- 구간 경계와 배점은 임시이다. 화면에 "참고용, 예측력 미검증" 문구를 붙인다
- 잔액 부족일의 임계값이 그달 반복 출금 합계라, 고정비가 큰 가게일수록 임계값도
  같이 커져 부족일이 늘어난다. 20점을 받는 조건이 월 0일인데 실제 소상공인 중
  통장 잔액이 항상 월 고정비 이상인 가게가 얼마나 되는지 확인되지 않았다.
  대부분이 낮은 구간에 몰리면 변별력이 없으므로 실데이터가 쌓이면 먼저 볼 항목이다
- 저점 회복은 매출이 어디쯤인지만 보는 항목이라 매출이 평탄하면 만점이 나온다.
  평탄하면서 적자인 가게도 이 항목은 20점을 받는데, 그 상태는 현재 상황 축이 잡는다.
  두 축을 함께 봐야 하며 한 축만으로 판단하지 않는다
- 주중 매출 비중 변화 10%p와 매출 변동계수 0.5는 견줄 공개 통계를 찾지 못했다
- 실데이터가 쌓이면 항목별 예측력을 확인해 배점을 조정하고, 그때 학습 모델로
  넘어가는 길이 열린다. 지금 규칙 점수가 그 출발점이다
