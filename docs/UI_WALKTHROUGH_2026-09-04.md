# 실제 화면 순회 점검과 개선

2026-09-04. 사용자 요청: 서비스 화면을 직접 사용하며 하나씩 개선.

## 확인한 화면과 반영 사항

| 실제 사용 중 확인한 문제 | 반영 |
|---|---|
| 시작 후 환영 제목이 남고 기본 정보·다음 버튼이 화면 밖으로 밀림 | 준비 단계별 제목, 간결한 입력 폼과 주제 선택. 골목 사진·종이 상담지 유지 |
| 빈 입력을 제출해도 해당 칸 안내가 없음 | 필수 표시·칸별 오류·첫 누락 필드 포커스. Enter로 다음 단계 |
| 생성 요청 중 동의 해제·정보 수정 가능 | 요청 중 관련 조작 잠금과 준비 상태 안내 |
| 채팅 화면 아래에 입력창이 멀리 떨어짐 | 대화 높이·입력칸 간격 조정, 중복 안내 제거, 가정 질문은 접힌 예시로 전환 |
| 새 질문이 도착하면 페이지 전체가 움직임 | 대화 기록/단계 목록의 내부 스크롤만 이동; reduced-motion 존중 |
| 단순 인사도 ‘답변 요약’으로 표시 | 근거 없는 요약 라벨 제거 |
| 채팅에서 음성 변경 시 마이크 동의가 빠져 403 후 자동 다운그레이드 | 현재 마이크 동의 확인 및 명시적 동의 UI, 연결 전 외부 AI 처리 동의 재검증. 권한·마이크 오류는 재시도 안내. 대체 방식은 사용자가 선택 |
| 방식 변경 후 새로고침하면 원래 방식으로 복귀 | 현재 mode를 URL에 동기화, 과거 autoplay 제거 |
| 질문·답변 접기 버튼이 닫히지 않음 | 선택과 펼침 상태 분리; 다른 질문 선택 시 해당 답변 다시 열림 |
| 관리자 목록 첫 기록의 액션이 첫 화면 아래로 밀림 | 전체 목록의 부적절한 개별 상담 단계 표시 제거, 간격 정리, 신규 접수 기본 접기 및 바로가기 연결 |
| 운영 화면에 PRIORITY·UNRESOLVED·정보 코드와 실제 동작보다 강한 종료 문구 | 표시용 한국어 상태/항목명, 계산 상세 접기, ‘완료 조건 검토’로 변경. 진행 중 하단 바 고정 해제 |
| 완료 기록 제목/검색/빈 상태가 ‘전체 상담 현황’, ‘평가’ 등으로 혼재 | 제목·검색 언어 일치, 초기 빈 상태와 검색 실패 분리, 검색 조건 초기화, 로딩/오류 중복 h1 제거 |

## 실제 브라우저 검증

- 먼저 Google 로그인된 GCP의 실제 첫 화면과 사장님 진입 화면을 열어 확인했다.
- 개인정보·운영 기록을 보존하기 위해 `127.0.0.1:3001`의 독립 DB에서 같은 코드를 실행했다. 운영 DB나 기존 로컬 인터뷰는 복사·수정하지 않았다.
- 검증용 문구점의 기본 정보 입력 → 외부 처리 동의 → 채팅 인터뷰 생성 → 실제 Sonnet 응답 → 우측 질문·답변 → 관리자 목록·상세 연결을 확인했다. 정해진 데모 응답을 사용하지 않았다.
- 비용 질문에 ‘답하고 싶지 않습니다’ → 재확인 한 번 → ‘답변하기 어려워요’ 선택 → 개선 방향 질문으로 이동함을 확인했다.
- 채팅 → 음성 전환 시 마이크 동의 UI와 비활성 시작 버튼 확인. 임의로 사용자의 마이크를 켜거나 브라우저 권한을 허용하지 않았다.
- 질문 다시 듣기 → ‘AI 질문을 음성으로 안내 중’/‘읽기 멈춤’ → 중지 → ‘다시 듣기’ 복귀를 확인했다. 실제 스피커 청취 품질 평가와는 구분한다.
- 상세 답변 접기 → 다른 질문 선택 → 그 질문의 원문 답변 다시 표시를 확인했다.
- 관리자 신규 접수 바로가기가 접힌 폼을 열고 해당 영역에 초점을 이동하는 것을 확인했다.
- 데스크톱 1266×720 브라우저 화면으로 확인했다. 모바일·200% 확대·장시간 실제 WebRTC 통화는 이번 검증 범위에서 완료하지 않았다.

## 코드 검증 및 남은 사항

- 단위/계약 테스트 93개 파일, 696개 테스트 통과. lint, typecheck, production build 통과.
- 전체 E2E 통과: 실제 역할별 라우트, 목록/상담 초안 저장·충돌·재시작, 인증/동의, 인터뷰 완료/강제 중단, 평가 목록, SSE, 음성 WS 재연결·전사 정정. E2E 공급자 스텁은 별도 테스트 전용이며 위 실제 API 브라우저 점검과 구분한다.
- 독립 환경에서 실제 채팅 답변 요청은 6.0–7.3초였다. 이번 화면 수정으로 모델 추론 자체가 통화 수준으로 빨라졌다고 주장하지 않는다.
- 실장치 WebRTC 양방향 통화/청취, 모바일 키보드, 초기 입력의 새로고침 복구, 외부 처리 동의를 철회한 후 재동의 UX는 추가 점검 대상이다. 기존 운영 인증·보존·금융 판단 금지 경계는 유지했다.

음성 연결 흐름 참고: [OpenAI 공식 WebRTC 안내](https://developers.openai.com/api/docs/guides/realtime-webrtc). 서버 키를 브라우저에 전달하지 않는 기존 단기 인증 구조를 유지한다.

## 공모전 목적 추가 점검

- 공식 대회 페이지와 기획서/기능명세서 HWPX를 읽고, 실제 제공 가치를 ‘소상공인 금융 상담 준비’로 명확히 했다. 골목 입구에서 대상·이용 흐름·미제공 기능을 확인할 수 있다.
- 사장님/관리자 모두 완료·불완전 종료 시 상담 메모를 받을 수 있다. 정확히 연결된 근거만 포함하고 0·모름·거절·해당 없음 상태를 보존한다. PDF는 브라우저 인쇄 기능을 이용한다.
- 독립 QA 인터뷰를 불완전 종료하는 실제 버튼 경로에서 확인 절차 배치 오류를 발견했다. 두 종료 방식에 필요한 확인을 공통으로 옮기고 확인 전 제출을 막았다. 서버 확인 정책은 유지했다.
- QA 기록 종료 후 실제 TXT 다운로드(3,448 bytes)를 열어 매출 15,000,000원, 원문 연결, 운영비 ‘확인 불가’, 6개 미확인 항목, 기록 버전 5를 대조했다. 운영 DB에는 해당 기록을 생성하지 않았다.
- 결과 화면의 밝은 배경에 흰 글씨가 남아 있던 대비 문제도 실제 스크린샷으로 확인하고 어두운 색으로 수정했다.
- 최종 단위/계약 검증: 94개 파일, 703개 테스트 통과. lint/typecheck/production build/E2E 통과. 브라우저 인쇄 대화상자의 PDF 파일 생성·사람의 실제 음성 청취는 별도 미검증이다.
- 심사 접근 권한과 제출 PDF는 아직 완료되지 않았다. 상세 범위는 `FINANCE_AI_CHALLENGE_2026.md` 참조.
