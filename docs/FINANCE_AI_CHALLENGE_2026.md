## 출품 포지셔닝

**동행금융AI — 기존 금융정보에 없던 사업자의 회복·운영·실행 정보를 AI 인터뷰로 수집하고, 근거 추적 가능한 금융 Feature로 변환하는 Alternative Data Generation Engine.**

대상은 자신의 사업 현황·변화 이유·개선 계획을 숫자와 서류만으로 설명하기 어려운 소상공인이다. 주 검토 경로는 실제 인터뷰 → 원문 Evidence → Canonical revision → `feature_schema_v2` → Improvement Signal의 입력과 제약 → 사람의 검토 → 사용자 Action → Recovery Mission이다. 7개 그룹의 100개 Feature 사전, 실제 서버 산식과 누락 상태, 원문까지의 lineage를 확인한다. AI는 질문과 비정형 대화 인터페이스를 맡고, 서버가 Canonical·Evidence·Feature·상태 전이·평가를 맡는다.

별도 `/modeling`의 정형 48개·인터뷰 30개·결합 16개 변수와 10개 규칙 항목은 기존 합성 거래자료 실험으로 보존한다. 이 94개 변수 시제품을 실제 인터뷰의 100개 v2 Feature 또는 검증된 학습 모델과 혼동하지 않는다.

금융 문제 해결의 범위는 ‘상담 전 정보 정리와 설명 부담을 줄이는 것’이다. 대출 심사 성능, 승인율 향상, 금융상품 추천 정확도, 신용위험 예측 성능을 검증하거나 제공한 것으로 주장하지 않는다.

## 기능명세서에 넣을 검증 절차

주 검토 경로는 가입·Google 로그인 없이 `/judge-demo`에서 다음을 확인한다. 입력은 합성 사례이며 실제 고객정보를 사용하지 않는다.

1. 0–20초: 홈과 ‘서비스 소개’에서 정보 공백·사용자/운영자 Flow를 보고 ‘3분 기술 데모 시작’으로 이동한다.
2. 20–70초: 외부 AI 처리 동의 후 합성 인터뷰를 생성하고 매출·고객, 고정비, 개선 계획의 3개 답변을 순서대로 전송한다. 미리 저장된 결과를 재생하지 않는다.
3. 70–110초: `2300만원` 원문 → `monthly_average_sales`의 23,000,000 KRW → 선택 revision과 Evidence를 확인한다.
4. 110–150초: `fin_sales_avg_3m=23000000`, 고정비 비율 `0.31`, 반복고객 비중 `0.50`을 확인한다. Feature Explorer에서 산식·출처·누락 정책·원문을 펼친다. 3답변의 서버 결과는 13 COMPUTED / 87 MISSING / 0 NOT_CALCULABLE이다.
5. 150–170초: 6개 Signal의 ‘왜?’에서 사용한 Feature·원문 근거·누락된 입력을 확인한다. 숫자는 신용점수가 아니며 임의 0~100 환산을 하지 않는다.
6. 170–180초: 원문·누락을 확인하고 INCOMPLETE FINAL을 저장한 뒤 개선 Action과 Recovery Journey에 진입한다. 전체 필수 질문을 마쳤다고 표시하거나 품질 등급을 생성하지 않는다.
7. 추가 검토: Action을 직접 선택하고 3개 미션에 합성 실행기록을 남긴다. NEW EVIDENCE와 `/review/:id`의 담당자 검토 상태를 확인한다. 새 기록은 원래 FINAL hash·Feature를 바꾸지 않는다.

별도 `/modeling`에서는 기존 10개 합성 거래 사례의 변수 결합 전후 산출·규칙·분모·근거 JSON을 검토한다. 분모가 달라진 축 결과 차이를 순수 인과 기여도나 실제 신용점수 개선으로 해석하지 않는다.

다음은 실제 음성·텍스트 전체 인터뷰를 더 살펴보는 보조 경로다.

아래는 합성 입력 예시이지 서비스에 미리 심어 둔 데모 기록이 아니다. 개인 신용·주민번호·계좌번호 등을 입력하지 않는다.

1. 공개 홈 → ‘인터뷰 시작’은 가상 카페 선택 상태로 진입한다. 공개 환경은 합성 프로필을 사용하며 실명·상호 입력을 요구하지 않는다.
2. 채팅 또는 음성을 선택한다. 실제 고객정보를 사용하지 않는다.
3. 외부 AI 처리 동의를 확인하고 채팅을 시작한다. 음성은 추가 마이크 동의와 브라우저 권한이 필요하다.
4. 매출 질문에 ‘최근 3개월 월평균 매출은 1500만원 정도입니다. 온라인 판매는 하지 않습니다’ 입력.
5. 원문 답변과 월평균 매출 15,000,000원이 연결되는지 확인. 자유 생성 질문의 문장 자체는 매번 같을 필요가 없다.
6. 비용 질문에 ‘답하고 싶지 않습니다’ → 한 번 더 확인하면 ‘답변하기 어려워요’. 더 반복하지 않고 다른 항목으로 이동하는지 확인.
7. 끝까지 응답하거나, 현재 답변과 종료를 명시적으로 확인한 뒤 미확인 항목을 남기고 종료한다. 불완전 종료에는 데이터 품질 평가를 생성하지 않는다.
8. 결과의 ‘상담 메모 받기 · TXT’를 눌러 원문/값/확인 상태/보류 항목/기록 버전을 대조한다. PDF는 브라우저 인쇄 대화상자의 ‘PDF로 저장’을 사용한다.
9. 권한이 있는 담당자 화면에서 같은 기록과 항목별 근거를 확인한다. 기관 접수·전송 완료로 표시하지 않는지 확인한다.

## AI·데이터 처리 범위

실제 인터뷰 입력은 사용자가 직접 입력한 기본 정보, 채팅/음성 답변, 명시적 동의다. 출력은 적응형 질문, 전사, 근거와 연결된 구조화 정보, 종료 기록, 상담 준비 메모다. 실시간 음성은 OpenAI WebRTC, 텍스트 처리에는 실제 Anthropic API를 사용하며 API 키는 서버 측에만 보관한다.

심사용 모델링 입력은 고정 시드로 만든 합성 카드매출·계좌·카드사용·서류·CB·인터뷰다. Python 원본이 생성한 `modeling_web_v1`을 Next 서버가 읽으며, 브라우저가 점수나 lineage를 재계산하지 않는다. 합성 모델링 사례와 방문자가 직접 만든 인터뷰 기록은 서로 다른 데이터 흐름이다.

원본 음성은 저장하지 않지만 전사·정리 정보·동의·감사 기록은 서버 DB에 저장된다. 데이터가 전혀 남지 않는 서비스라고 설명하지 않는다. 결과 파일에는 답변 원문이 포함되며 사용자가 직접 내려받고 공유한다. 금융기관으로 자동 전송하지 않는다.
