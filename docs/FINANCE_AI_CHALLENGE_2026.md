## 기능명세서에 넣을 검증 절차

주 검토 경로는 로그인 없이 다음을 확인한다.

1. 공개 홈 → ‘서비스 소개’에서 목적과 두 관점 Flow → ‘변수와 평가 결과 살펴보기’.
2. ‘정형 데이터만’에서 현재 상황 78, 개선가능성 40(24/60), ‘맥락 변수 결합’에서 현재 상황 78, 개선가능성 67.5(54/80)를 확인한다.
3. 영업일 감소 해소 변수를 찾아 원문·전후 값·매출 방향 항목의 0→10점 연결을 확인한다. 분모가 달라진 축 점수 차이를 순수 기여도로 해석하지 않는다.
4. 답변 없음 사례로 바꾸면 해당 사례의 개선가능성 30이 표시되는지 확인한다. 모델 평가 탭에서도 같은 사례의 비교가 나오는지 확인한다.
5. CB 대조와 동일 변수 재평가, 검증 한계, 근거 JSON을 확인한다.

다음은 별도 실제 입력 체험이다.

아래는 합성 입력 예시이지 서비스에 미리 심어 둔 데모 기록이 아니다. 개인 신용·주민번호·계좌번호 등을 입력하지 않는다.

1. 공개 홈 → ‘가입 없이 바로 체험’은 가상 카페 선택 상태로 진입한다. 다른 업종을 직접 입력하려면 `/borrower`로 이동한다.
2. 호칭 ‘검증 사장님’, 상호 ‘검증 문구점’, 업종 ‘오프라인 소매점’ 입력. 실제 사업으로 오인하지 않게 합성 이름을 사용한다.
3. 외부 AI 처리 동의를 확인하고 채팅을 시작한다. 음성은 추가 마이크 동의와 브라우저 권한이 필요하다.
4. 매출 질문에 ‘최근 3개월 월평균 매출은 1500만원 정도입니다. 온라인 판매는 하지 않습니다’ 입력.
5. 원문 답변과 월평균 매출 15,000,000원이 연결되는지 확인. 자유 생성 질문의 문장 자체는 매번 같을 필요가 없다.
6. 비용 질문에 ‘답하고 싶지 않습니다’ → 한 번 더 확인하면 ‘답변하기 어려워요’. 더 반복하지 않고 다른 항목으로 이동하는지 확인.
7. 끝까지 응답하거나, 현재 답변과 종료를 명시적으로 확인한 뒤 미확인 항목을 남기고 종료한다. 불완전 종료에는 데이터 품질 평가를 생성하지 않는다.
8. 결과의 ‘상담 메모 받기 · TXT’를 눌러 원문/값/확인 상태/보류 항목/기록 버전을 대조한다. PDF는 브라우저 인쇄 대화상자의 ‘PDF로 저장’을 사용한다.
9. 권한이 있는 담당자 화면에서 같은 기록과 항목별 근거를 확인한다. 기관 접수·전송 완료로 표시하지 않는지 확인한다.

## AI·데이터 처리 범위

실제 인터뷰 입력은 사용자가 직접 입력한 기본 정보, 채팅/음성 답변, 명시적 동의다. 출력은 적응형 질문, 전사, 근거와 연결된 구조화 정보, 종료 기록, 상담 준비 메모다. 실시간 음성은 OpenAI WebRTC, 텍스트 처리에는 실제 Anthropic API를 사용하며 API 키는 서버 측에만 보관한다.

심사용 모델링 입력은 고정 시드로 만든 합성 카드매출·계좌·카드사용·서류·CB·인터뷰다. Python 원본이 생성한 `modeling_web_v1`을 Next 서버가 읽으며, 브라우저가 점수나 lineage를 재계산하지 않는다. 합성 모델링 사례와 방문자가 직접 만든 인터뷰 기록은 서로 다른 데이터 흐름이다.

원본 음성은 저장하지 않지만 전사·정리 정보·동의·감사 기록은 서버 DB에 저장된다. 데이터가 전혀 남지 않는 서비스라고 설명하지 않는다. 결과 파일에는 답변 원문이 포함되며 사용자가 직접 내려받고 공유한다. 금융기관으로 자동 전송하지 않는다.
