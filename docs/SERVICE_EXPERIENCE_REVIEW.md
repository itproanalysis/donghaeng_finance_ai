# 동행 골목길 — 실제 서비스 UX 점검·개선

작성일: 2026-09-04

## 범위와 방향

사장님 인터뷰뿐 아니라 입구, 관리자 관제, 인터뷰 검토, 종료 기록, 평가 상세, 상담 준비까지 같은 길찾기 체계를 적용했다. 골목길은 실사용 흐름의 안내 방식이며, 미리 정해 둔 사례·대화·점수로 실제 기능을 대체하지 않는다.

Sites 스킬의 접근성·반응형·실제 데이터 기반 UI 원칙을 적용했다. 다만 이 서비스는 Next custom server, SQLite, SSE/WebSocket, 로컬 음성 런타임을 사용한다. `frontend-prototype`의 별도 Sites 프로젝트로 운영 서비스를 옮기거나 외부에 배포하지 않았다.

| 업종 가정 | 관리자 접수에서 카페 기본 선택 | 업종 미선택 상태에서 시작, 사장님·사업체·업종 명시적 확인 필수 |

| 사장님 오른쪽 패널 | 여러 분석 카드 아래에 질문·답변 이력이 묻힘 | 질문·답변을 기본 패널로, 사업 지도·한 줄 정리·개선 판을 별도 선택 패널로 구분 |

| 근거 보존 | 초안과 FINAL 원본의 관계가 불명확 | 초안은 별도 테이블, 저장 감사 이벤트 생성. FINAL·평가 원문은 변경하지 않음. 기관 접수/전송으로 오인하지 않도록 표시 |
| 현재 실행 환경 | 장기 실행 중인 dev server가 DB v15를 유지해 새 초안 API에서 500 | SQLite 온라인 백업 후 기존 마이그레이션 실행기로 v16 적용. `quick_check=ok`, 실제 초안 GET 200 확인 |

## 화면과 데이터 동선

```text
동행 골목길 입구
├─ 사장님: 가게 소개 → 방식·처리 동의 → 한 대화 → 내 답변 확인 → 개선 방향 살펴보기
└─ 관리자: 상담소 사례 선택 → 인터뷰·근거 검토 → 개선 초안 → 자료 점검 → 기관 상담 준비
                             └─ 새 인터뷰 접수
```

- 새로고침 시 새 질문·가상 답변을 만들지 않고 해당 ID의 저장 기록을 읽는다.
- 관제판은 마지막 조회 시각을 표시하고 명시적 새로고침으로 갱신한다. 마이크 상태를 실시간 감시하는 화면은 아니다.
- 불완전 종료에는 평가를 임의로 생성하지 않는다. 상담소에서 종료 기록으로 안내한다.
- 정리되지 않은 정보와 답변 거절/확인 불가를 구분한다. 거절/확인 불가는 남은 필수 항목으로 다시 계산하지 않는다.
- 보조 데이터 품질 등급과 공식 신용평가·승인 판단의 경계를 유지한다.

## 새 API와 저장 계약

- `GET /api/interviews?q=&status=ALL&limit=24&offset=0`
  - `ADMIN` 또는 `INTERVIEWER` 역할 필요, tenant 범위 제한.
  - `limit` 1–100, `offset` 0–100000, 검색어 100자 이내.
  - 전체 상태 수는 기관 전체 기준, 검색 결과 수·페이지는 현재 필터 기준.
- `GET /api/interviews/{id}/consultation-draft`
  - 저장 전 revision 0, 빈 선택을 반환.
- `PUT /api/interviews/{id}/consultation-draft`
  - 동일 출처의 인증된 담당자만 가능.
  - `{ expectedRevision, data: { proposalId, owner, period, documents, reviewed, institutionId } }`.
  - 입력 allowlist와 기관/자료 enum 검증. 버전 불일치 409.
  - 직전 revision의 동일 내용 재전송은 새 버전·감사 이벤트를 중복 생성하지 않음.
  - 최종 인터뷰/평가 원본과 별개로 저장. 금융기관 자동 전송 없음.

OpenAPI 문서와 런타임 경로·응답 계약 테스트를 함께 갱신했다.

## 검증 기록

- `npm run lint`: 오류·경고 없음.
- `npm run typecheck`: 통과.
- `npm test`: 87개 파일, 575개 테스트 통과 (기존 529개 + 이번 회귀/서버/API 테스트 46개).
- `npm run build`: 프로덕션 빌드 통과.
- `npm run test:e2e`: 프로덕션 custom server를 별도 포트·임시 DB로 띄워 아래 흐름 통과.
  - 실제 역할 페이지 HTTP 렌더링, 옛 시연 주소 리다이렉트
  - 빈 관제판 → 인터뷰 생성 → 실제 사례/완료 평가 연결
  - 초안 저장 → 충돌 거절 → 프로세스 재기동 → 같은 초안 복원
  - 인증·tenant·CSRF, 동의, 오디오 WS 재연결, STT 메타데이터, 전사 정정, SSE 재생, 핵심/확장 문항 종료·평가, 불완전 종료
- 현재 `127.0.0.1:3000`에서도 입구·사장님 시작·상담소·평가 목록 HTTP 200 및 새 컴포넌트 마커 확인. 실제 사례 조회와 초안 조회 200 확인. 기존 기록을 테스트 사례로 덮어쓰지 않음.
- 실제 DB 변경 전 온라인 백업: `data/before-consultation-v16-20260904-1135.db` (Git 제외). DB 삭제·초기화 없음.
- 마이그레이션 전후 인터뷰·전사·근거·FINAL·평가 행 수가 동일하고, 기존 FINAL 콘텐츠 해시도 동일함을 읽기 전용 비교로 확인했다.

E2E 외부 AI/STT는 네트워크 계약을 검증하는 로컬 스텁이다. 실제 서비스에는 스텁을 연결하지 않았다. 이번 검증으로 실제 마이크 입력·스피커 음질·OpenAI 왕복 지연이나 화면의 픽셀 수준 검수를 완료했다고 주장하지 않는다.

## 남은 확인 및 운영 범위

### 골목 분위기 복원 — 후속 수정 (2026-09-04)

사용자 피드백: “AI 티”가 강하고 초기 골목의 공간감이 사라짐.

- 초기 `frontend-prototype/DESIGN.md`의 원칙을 다시 적용했다. 중앙 길은 비우고 원본 `korean-alley-cafe-integrated-8k.webp`를 입구 전체 화면으로 복원했다. 큰 역할 카드·서비스 장점 카드·중복 설명은 걷어냈다.
- 두 실제 역할 링크는 처음부터 노출한다. 스크롤 퀘스트, 타이머, 장면 완료를 기다릴 필요가 없다. 새 `AlleyEntranceScene`은 포인터에 반응하는 작은 시점 이동만 담당하며 인터뷰/API/진행률과 연결되지 않는다. 터치·감소 모션에서는 고정 장면이다.
- 로고는 `동행금융`, 문구는 `가게 소개 / 인터뷰 / 상담 대장 / 완료 기록 / 상담 준비서`처럼 구체적인 일 중심으로 다듬었다. 장식용 반짝이, 사장님 화면의 생성 인물 사진, 반복되는 영문 표제를 제거했다.
- 사장님 준비 화면은 골목 옆 종이 안내문, 대화·완료 화면은 상담 기록지, 관리자는 서류 대장 형태로 통일했다. 관리자 기본 보기는 목록이며 카드 보기 선택은 유지한다.
- 음성 연결의 기술명은 펼쳐보기로 옮겼다. AI 사용 안내, 외부 처리 동의, 실제 모델 정보, 마이크·다시 듣기·종료 버튼과 오류 표시는 유지한다. 음성/API 동작은 변경하지 않았다.
- 모바일 복귀 링크가 기존 CSS에 의해 숨겨지던 문제를 수정했다. 작은 높이의 화면에서 첫 진입 여백을 줄이고, 기본정보/방식 선택 시 제목으로 키보드 포커스를 옮긴다. 감소 모션·명시적 포커스 테두리·모바일 단일 열 배치를 포함한다.
- 검증: 88개 파일/584개 테스트 통과. 실제 컴포넌트의 서버 렌더링 검사 5건을 포함한 새 회귀 검사 9건 추가. lint·typecheck·프로덕션 빌드 및 해당 빌드의 E2E 재실행 통과.
- 로컬 실행 서버의 역할별 URL 응답을 확인했다. 브라우저 픽셀/실기기 청취 검수는 수행하지 않았으며, 아래 운영 확인 사항은 여전히 별도다. 서버 기록 삭제, 새 마이그레이션, API 키 변경, 외부 배포는 하지 않았다.

### 운영 전 추가 확인

1. 실제 장치에서 음성 첫 인사, 연속 3회 응답, 끼어들기, 다시 듣기, 연결 실패 폴백을 확인해야 한다. 외부 API 키·마이크 권한·로컬 STT/TTS 실행 상태에 영향을 받는다.
2. 모바일 실제 브라우저, 확대, 스크린리더, 저장 중 탐색을 수동 확인해야 한다. CSS에 반응형·키보드 포커스·최소 터치 영역·reduced-motion을 반영했지만 실제 시각 QA와 동일하지 않다.
3. 외부 IdP는 기존 코드에서 미구현이며 production 인증은 fail-closed다. 현재 loopback 로컬 작업공간과 실제 여러 기관의 공개 운영을 동일시하면 안 된다. 외부 공개 전 계정/역할 발급·감사·접근 범위 설계가 필요하다.
4. 기관 연계는 공식 안내 확인과 상담자료 초안 다운로드까지다. 실제 신청·접수·개인정보 제3자 전송, 증빙 원본 업로드, 실행 성과 수집은 구현된 것으로 표시하지 않았다.
5. 기존 `frontend-prototype`·디자인 원본·개발 중인 배포 스크립트는 보존했다. 현재 서비스 동선과 분리했으며 이번 작업에서 Git push나 외부 배포는 하지 않았다.
