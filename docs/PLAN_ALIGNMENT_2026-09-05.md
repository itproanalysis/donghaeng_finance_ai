# 기획안 의도와 서비스 반영

확인한 원본: `기획안/ChatGPT Image 2026년 8월 9일 오후 10_49_34 (1).png`부터 `(10).png`까지 10장. 문서형 기획서가 아니라 화면 기획 이미지다. 전체 화면을 직접 읽고 아래 의도를 추출했다.

## 원안의 목적

CB 정보만으로 설명하기 어려운 고객의 사업 현황과 행동 변화를 대안데이터로 만들고, 목표 수행 기록을 축적해 재평가와 금융기관 검토에 연결한다. 인터뷰는 정보 수집 단계이며, 서비스의 핵심 결과는 **변수·평가 근거·실행 변화·후속 검토자료**다.

최근 사용자 요청인 모델링 중심, 서비스 완성도, 과한 AI 표현 제거를 함께 적용했다. 이미지의 레이아웃을 그대로 복제하거나 가상 실적·금리·승인 확률을 실제 기능처럼 표시하지 않았다.

## 모델과 수행기록의 연결

- 최초 기준일: 2026-07-31. 후속 기준일: 2027-01-31. 미래 날짜를 포함한 **합성 시나리오**이며 실제 관측 이력이 아니다.
- 목표: `biz_operating_day_count_avg_3m`, 최초 23.6667일 → 180일 목표 29일.
- 후속 자료: `case_operating_drop_after/card_sales.csv`의 월별 집계를 기존 `modeling.features.card_sales.monthly` 결과에서 가져온다.
- 최종 최근 3개월: 2026-11 30일, 2026-12 31일, 2027-01 31일. `(30 + 31 + 31) ÷ 3 = 30.6667일`로 목표를 충족한다.
- 별도 가산 규칙을 만들지 않았다. 새 거래자료는 기존 `modeling.build`와 `modeling.scorecard`로 처리한다.
- 현재 상황: 78(78/100) → 100(100/100). 개선가능성: 67.5(54/80) → 100(60/60). 재평가의 개선가능성은 3/5항목만 반영되므로 신용 개선률이나 승인 가능성 상승으로 읽지 않는다.
- 과거 인터뷰 30개는 재사용하지 않는다. 목표는 비교 기준으로만 보존하며 ‘계획의 현실성’은 후속 점수에서 제외된다.
- 목표 확인·수행자료 확인·담당자 메모는 브라우저 검토 기록이며 점수 입력으로 사용하지 않는다. 모델 버전과 사례별로 분리 저장한다.

## 함께 수정한 품질 문제

1. 특정 재평가 사례가 모든 선택 사례에 표시되던 혼선 제거.
2. 사례 선택과 대상 탭 이동을 한 URL 변경으로 처리해 서로 다른 사례·탭 상태가 겹치지 않도록 변경.
3. 홈의 손님 감소·객단가 하락 예시 산식이 실제 점수와 달랐던 문제 수정. 수기 산식 대신 산출물의 배점·분모 사용.
4. 평가 반영 화면에서 영업일 감소 사례의 수치와 잘못된 제외 사유를 모든 사례에 표시하던 고정 설명 제거. 실제 화면 산식의 사례별 회귀 검사 추가.
5. 과도한 ‘심사위원 3분 가이드’, 장식 배지·중복 사례 버튼을 실제 업무 단계 탐색으로 교체.
6. 서비스 소개를 원안의 사용자·운영자 6단계 한 페이지로 정리.
