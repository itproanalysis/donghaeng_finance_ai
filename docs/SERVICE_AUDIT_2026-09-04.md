# 현재 서비스 점검과 개선

범위: 실제 진입/역할 동선, 사장님 인터뷰·음성, 관리자 조회·기록, 인증·동의·저장, GCP 배포. 기존 골목 UI와 사용자 기록은 보존했다.

## 이번 발견 및 조치

| P0 | 로컬 SQLite와 Windows 음성 엔진은 클라우드에서 그대로 동작하지 않음 | 별도 영구 디스크 VM, 재기동/마운트 정책, Secret Manager 메모리 주입. 실제 클라우드 Realtime/STT/TTS 연결 |
| P0 | 클라우드로 바뀐 TTS 경로에 인터뷰별 외부 처리 동의 확인이 없었음 | 개인화 TTS 전 현재 동의·tenant 소유권 검사. 동의 철회 시 다시 거절. 인터뷰 없는 요청은 고정 비개인 문구만 허용 |

| P1 | `%`, `_` 검색이 SQL 와일드카드로 동작 | literal escaping, tenant 조건 유지. limit/offset 범위·담당자 역할 검사 추가 |
| P1 | GCP에서 로컬 비밀번호 화면으로 진입 가능 | IAP 환경 로그인 화면 내부 이동, 안전한 복귀 경로 allowlist 및 외부/역슬래시/경로 우회 차단 |
| P2 | 클라우드 음성이 Qwen으로 기록됨, 준비 전 '음성 준비됨' 표시 | 서버 응답의 실제 공급자 분류 반영, 기기 대체 음성 구분, 재생 전 준비 완료 단정 제거 |

## 검증 증적

- lint / TypeScript: 통과.
- 자동 테스트: **91개 파일, 682개 테스트 통과**. IAP 서명·키 캐시·권한, tenant 격리, 완료 목록 페이지·검색, 동의 후 음성/철회, 로그인 복귀 경로, 음성 재연결 회귀 포함.
- 프로덕션 빌드 성공.
- production-like E2E: 실제 역할 라우트/옛 주소 리다이렉트, 인터뷰 생성·완료·평가·강제 중단, SQLite 초안 저장/재기동 복원/409 충돌, 인증/CSRF/동의, WS 재연결/STT 메타데이터, 전사 정정, SSE 재생, 핵심 8항목·확장 11항목 흐름 통과.
- E2E는 별도 포트·임시 DB 및 외부 공급자 스텁을 쓴다. 실제 사용자의 로컬/GCP 인터뷰를 테스트 자료로 덮어쓰지 않았다.
- 별도로 GCP에서 실제 Sonnet 5, Realtime 2.1, TTS marin, 한국어 STT 호출과 Realtime 음성 입출력을 검증했다. 자세한 관측값은 `GCP_LIVE_SERVICE.md` 참조.
- 실제 GCP 브라우저에서 Google 로그인 후 골목 입구 및 담당자 본인 세션/초기 상담 대장 조회 확인.
- 재배포 후 완료 기록 검색 결과 로딩, `/login?next=/borrower`의 Google 인증 복귀, 사장님 시작 → 기본정보 단계 이동과 제목 포커스도 확인했다. 기본정보 입력/실제 인터뷰 생성은 하지 않아 GCP에 검증용 가상 사례를 남기지 않았다.
- 실제 서비스에 개선 이미지 `b94661d7-ca14-4e4f-b536-57cc95e90538` 배포. 게이트웨이 revision `donghaeng-finance-ai-00004-d6p` Ready. 재시작 후 DB v16 / `quick_check=ok` / 초기 인터뷰 0건 유지.
- backend의 비인증 페이지·API 및 위조 assertion 모두 HTTP 401, VM 외부 IP:3000 접속 차단 확인. 앱 소스/배포 자산에서 실제 공급자 키 패턴 검출 없음.

## 운영 확대 전에 남은 점검

1. 실제 브라우저/장치에서 30분 통화, 끼어들기, 장기 일시정지, 네트워크 변경, TTS→마이크 echo, 접근성/모바일 검수.
2. 정기 백업/실제 복원 리허설, 장애 알림, 부하·메모리·비용 상한 운영 정책. 현재는 한 계정·단일 VM 범위다.
3. 별도 사장님/기관 계정 발급과 역할/사례별 권한, 실제 고객 개인정보·외부 공급자 보존/처리·모델 거버넌스 승인.
4. 금융기관 연결은 준비서/공식 안내 범위. 자동 대출 접수·승인·실행 성과 수집을 구현된 것으로 표시하지 않는다.

완료된 코드 테스트, 실제 API 연결, 아직 필요한 실기기/운영 검증을 구분했다. 이번 점검만으로 서비스 전체의 모든 결함이 없다는 뜻은 아니다.
